# Green Target invoice creation on one page

Implemented 2026-09-28. No schema migration or historical data correction is needed. Deploy frontend and backend together using the existing deployment process; deploy the backend first if they must be released separately. Existing invoice callers remain compatible.

## Save behavior

- Existing rentals automatically select their customer; there is no separate customer selector for this flow. **Add new rental** reveals customer selection/creation only when no customer has been selected yet. A new customer is saved immediately, even if the invoice is later abandoned. Billing address is separate from the rental service location.
- The existing quick picker still starts with all unbilled rentals across customers. Picking one selects its customer and does not add a new rental draft. Further choices narrow to that customer. **Browse all unbilled rentals** returns to the full picker after confirming that the current rental selection can be cleared.
- The optional e-Invoice section uses the existing customer identity validation and Sabah state default. A customer can be created with only a name; individual e-Invoice submission still needs the existing required identity and phone details.
- The page starts without rental drafts. Choosing a customer through **Add new rental** adds one removable draft; adding rentals after selecting existing rentals uses their customer automatically. Add more drafts or keep only existing rentals. Adding a location saves it immediately and selects it for that rental.
- New rentals require a driver. The first driver is selected initially; added rows inherit the previous row's driver. The first saved location is selected by default and can be cleared. Dumpsters remain optional.
- Invoice quantity defaults to the combined count of new and existing rentals at RM200 each until invoice lines are manually edited. Removing rentals or changing customers does not overwrite manually edited invoice lines.
- The customer card previews the bill address separately for PDF and individual e-Invoice. A customer billing address overrides service locations in both. Otherwise PDF lists distinct site/address labels in rental-ID order; individual e-Invoice uses the first nonblank rental address in rental-ID order plus all distinct site names. Existing rentals precede unsaved drafts. The preview reuses the MyInvois three-line wrapping helper, including its length warning; it does not change invoice payloads or saved addresses.
- `POST /greentarget/api/invoices` accepts `new_rentals: [{ driver, location_id, tong_no }]`. It creates these rentals and the invoice/journal in one transaction. Rental drafts are not saved by the standalone rental endpoint.
- Placement/pickup dates and remarks are NULL; the active default destination is selected server-side, or NULL when none exists. Dateless rentals do not reserve dumpsters, change availability, or generate dated driver-trip suggestions.
- Payments and e-Invoice submission still follow invoice creation separately. A failure there keeps the saved invoice and its rentals, using the existing recovery flow. Previously saved customers/locations and the existing debtor-identity preparation are outside the invoice transaction.

## Manual acceptance scenarios

Use the development environment and disposable records. These application scenarios have not been executed automatically.

1. **Minimal invoice:** Click **Add new rental**, select an existing customer, keep the first driver, select no location and no dumpster, and create an invoice. Check one linked rental, NULL dates/remarks, the configured default destination, the expected RM200 line, and the GT sales journal.
2. **Quick picker, multiple and mixed rentals:** Before choosing a customer, search/page through all unbilled rentals and pick one. Verify its customer is selected and no new rental draft is added. Add a draft and another draft, verify driver inheritance, and select more existing unbilled rentals across search results/pages. Verify quantity/amount reflect the combined count. Remove every draft and save an existing-only invoice. Removing the final existing selection must retain the customer; saving with no rentals must fail. Use **Browse all unbilled rentals** to choose another customer's work.
3. **Manual invoice lines:** Change quantity, description or price, then add/remove rentals and change customers. Keyed invoice lines must remain intact; account allocations must continue to match the total before saving.
4. **New customer:** Create a name-only customer and issue an invoice. Repeat with phone/billing address and complete, validated e-Invoice details. Incomplete or invalid identity information must keep the modal values and create no customer. Cancelling an invoice after creating a customer must leave that customer available.
5. **Locations and dumpsters:** Verify first-location default, explicit no-location selection, a newly added address without a Site, optional Site/phone, and optional dumpster. A newly created location must be selected on its target draft. Check that dumpster status/availability does not change for a dateless rental.
6. **Customer switching and delayed responses:** Confirm and cancel customer changes with draft and existing rentals selected. Confirmed changes must clear old rentals/locations and use the next customer's debtor default. Delay customer/rental/location requests and switch/search quickly; old results must not replace the current selection. Empty customer lists must still allow creating a customer; failed reference requests must offer retry. A location-load failure must allow explicitly selecting no location.
7. **Navigation and editing:** Open invoice creation with a supplied customer/rental ID outside the first picker page. That rental must load without an extra draft. Open existing invoices, including ones with receipts, adjustments or valid e-Invoices; current editing restrictions must hold. Check the Rental Details invoice-creation action still works. Edit a rental whose driver is no longer in the active list: its driver must remain displayed and preserved.
8. **Failures and concurrency:** Try a duplicate invoice number, a posting-locked date, an invalid dumpster, another customer's location, another customer's rental and an already-billed rental. Confirm rejected invoice saves leave no new rental, invoice link, invoice line or sales journal. Retry corrected requests. Submit two invoices for the same unbilled rental concurrently: only one may succeed. Rapid duplicate clicks must issue only one request from the form.
9. **Connected screens:** Check invoice detail/PDF and rental-list links, service location and billing-address precedence in e-Invoices, immediate full/partial payments, pending cheques and receipt joins. A post-save payment/e-Invoice failure must retain the invoice and linked rentals for recovery.
10. **Presentation:** Check desktop/mobile layouts, keyboard operation, driver pills, modal submit/cancel, unsaved-change confirmation and English/Malay/Chinese labels. Open location and dumpster dropdowns above the existing-rental list: all options must display above the sticky customer headers. Opening/cancelling **Add new rental** without choosing a customer must leave quantity at zero and the form unchanged; selecting an existing rental must hide customer setup and show its customer as read-only text.

Run `npm run i18n:report` for translation-key symmetry. Build, type checks, lint and application tests remain manual at the user's request.

Address-preview checks: compare the previews with the saved PDF and individual e-Invoice for a customer with a billing address, a customer without one, mixed existing/new rentals, repeated locations/site names, no location, and a location created inline. Change/remove draft locations and switch customers; previews must update without retaining the previous customer's text. Select existing rentals out of ID order and check the first e-Invoice address matches rental-ID order, prioritizing nonblank addresses. Delay or fail location loading; show the waiting state until data is available or no location is explicitly selected. An overlong address must show the MyInvois length warning rather than silently truncate. For no location and no billing address, the existing outputs remain `-` on PDF and `Tong Location` on the individual e-Invoice.
